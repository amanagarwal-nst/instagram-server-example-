Core Modules & the Module System

Big idea: a module is one file. Its code is private; it shares only what it exports.
Analogy: each file is a tiffin box. Nothing leaks out unless you open the lid (export). Another file takes what it needs with require or import.
KindComes fromExampleLoad with
Core (built-in)Comes with Nodefs, path, http, events, osrequire('fs')
LocalA file you wrote./menu.jsrequire('./menu')
Third-partynpm (node_modules)expressrequire('express')

Example A: CommonJS (the default in Node)

menu.js
// menu.js
const items = [
  { id: 1, name: 'Masala Chai', price: 20 },
  { id: 2, name: 'Samosa', price: 15 },
];

function formatPrice(p) {          // private: not exported
  return 'Rs. ' + p;
}

function listMenu() {
  return items.map(i => i.name + ' - ' + formatPrice(i.price));
}

function findItem(id) {
  return items.find(i => i.id === id);
}

module.exports = { listMenu, findItem };   // open the lid
app.js
// app.js   ->   run: node app.js
const os = require('os');                         // core module
const { listMenu, findItem } = require('./menu'); // local module

console.log('Running on:', os.platform());
console.log(listMenu());
console.log(findItem(2).name);                    // Samosa

Example B: ES Modules (modern syntax)

menu.mjs
// menu.mjs
export const SHOP_NAME = 'ChaiCart';            // named export

export function listMenu() {                     // named export
  return ['Masala Chai - Rs. 20', 'Samosa - Rs. 15'];
}

export default function greet(name) {            // default export (only one)
  return 'Welcome, ' + name;
}
app.mjs
// app.mjs   ->   run: node app.mjs
import greet, { SHOP_NAME, listMenu } from './menu.mjs'; // extension needed

console.log(greet('Aman'));
console.log(SHOP_NAME, listMenu());

Must-remember points

  • require() caches: a module's code runs only once, however many times it is required.
  • exports = {...} does not work; always use module.exports = {...}.
  • A file can have many named exports but only one default export.

Segment 2 of 12

Event-Driven Programming

Big idea: instead of asking "is it done yet?", code says "tell me when it happens" and moves on.
Analogy: a token counter. The shopkeeper shouts "Token 42!" (emit). Everyone waiting for 42 reacts (on). Someone who only wants the first free sample listens once.
MethodWhat it does
on(event, fn)Run fn every time event is emitted
once(event, fn)Run fn only the first time, then remove it
emit(event, ...data)Fire the event and pass data to listeners
off(event, fn)Remove a listener
listenerCount(event)How many listeners are attached

Example: the order counter

events-demo.js
// events-demo.js   ->   run: node events-demo.js
const EventEmitter = require('events');
const shop = new EventEmitter();

// on(): runs for EVERY order
shop.on('order', (name, item) => {
  console.log(`Kitchen: making ${item} for ${name}`);
});

shop.on('order', (name) => {
  console.log(`Cashier: billing ${name}`);
});

// once(): runs only for the FIRST order
shop.once('order', (name) => {
  console.log(`Free biscuit for ${name}!`);
});

// always handle 'error', or the program crashes
shop.on('error', (err) => {
  console.log('Error:', err.message);
});

shop.emit('order', 'Aman', 'Chai');
shop.emit('order', 'Priya', 'Samosa');
shop.emit('error', new Error('Milk finished'));

console.log('Order listeners left:', shop.listenerCount('order'));

Output:

Kitchen: making Chai for Aman
Cashier: billing Aman
Free biscuit for Aman!
Kitchen: making Samosa for Priya
Cashier: billing Priya
Error: Milk finished
Order listeners left: 2

Must-remember points

  • Listeners run synchronously, in the order they were added.
  • once removes itself after one run, so the count dropped from 3 to 2.
  • Emitting 'error' with no listener crashes the program.
  • HTTP servers, streams and process are all EventEmitters.

Self-check: answer out loud, then reveal

  1. Difference between on() and once().
    on runs on every emit; once runs on the first emit and then removes itself.
  2. How do you pass data from emit() to a listener?
    Extra arguments to emit reach the listener: emit('order', 'Aman', 'Chai') → (name, item) => ....
  3. What happens if 'error' is emitted and nobody listens?
    Node throws the error and the program crashes.
  4. Name two built-in objects that are EventEmitters.
    Any two: HTTP server, streams, process, req.

The File System (fs) Module

Big idea: the fs module reads, writes, appends, renames and deletes files.
Analogy: synchronous = standing at the counter until your chai is ready while the queue waits. Asynchronous = take a token, sit down, get called when ready.
SynchronousAsynchronous
Examplefs.readFileSync(f, 'utf8')fs.readFile(f, 'utf8', callback)
Blocks the program?YesNo
ResultReturned directlyGiven to a callback / promise
Errorstry / catcherr is the callback's first argument
Use it forSmall scripts, startupServers and real apps

Example A: see the order for yourself

sync-vs-async.js
// sync-vs-async.js
const fs = require('fs');

fs.writeFileSync('note.txt', 'Chai is ready');   // create a file

console.log('1. Start');

const data = fs.readFileSync('note.txt', 'utf8'); // waits here
console.log('2. Sync read:', data);

fs.readFile('note.txt', 'utf8', (err, text) => {  // does NOT wait
  if (err) {
    console.log('Error:', err.message);
    return;
  }
  console.log('4. Async read:', text);
});

console.log('3. End of file');

Output order: 1, 2, 3, 4. The async callback runs last because Node finished the rest of the code first.

Example B: everyday file handling (promise style)

files.js
// files.js
const fs = require('fs/promises');

async function main() {
  try {
    await fs.writeFile('orders.txt', 'Aman - Chai\n');      // create / overwrite
    await fs.appendFile('orders.txt', 'Priya - Samosa\n');  // add to the end

    const text = await fs.readFile('orders.txt', 'utf8');   // read
    console.log(text);

    await fs.mkdir('backup', { recursive: true });          // make a folder
    await fs.rename('orders.txt', 'backup/orders.txt');     // move the file
    console.log(await fs.readdir('backup'));                // [ 'orders.txt' ]

    await fs.unlink('backup/orders.txt');                    // delete it
    console.log('Deleted!');
  } catch (err) {
    console.log('Something went wrong:', err.message);
  }
}

main();

Self-check: answer out loud, then reveal

  1. Three differences between synchronous and asynchronous file operations.
    Sync blocks / async doesn't; sync returns the value / async uses a callback or promise; sync uses try/catch / callback gets err first.
  2. What is an error-first callback?
    A callback whose first parameter is the error (or null): (err, data) => {}.
  3. writeFile vs appendFile?
    writeFile replaces the content; appendFile adds to the end.
  4. Why should a web server avoid readFileSync?
    It blocks the single thread, so all other users wait.

Process & Path

Big idea: process tells your program about itself and its surroundings. path builds file paths that work on every OS.
Analogy: process is your program's ID card. path is Google Maps for files: it uses / on Linux/Mac and \ on Windows automatically.

Example: one script, every important feature

info.js
// info.js
// run:  node info.js Aman 3
// with env vars (Linux/Mac):  SHOP_NAME=TapriTime node info.js Aman 3
const path = require('path');

// 1. Command-line arguments (real ones start at index 2)
const args = process.argv.slice(2);
const name = args[0] || 'Guest';
const cups = Number(args[1]) || 1;           // arguments are strings!
console.log(`${name} ordered ${cups} cup(s) = Rs. ${cups * 20}`);

// 2. Environment variables (also strings)
const shop = process.env.SHOP_NAME || 'ChaiCart';
const port = Number(process.env.PORT) || 3000;
console.log(`Shop: ${shop}, Port: ${port}`);

// 3. Other useful process info
console.log('Node version:', process.version);
console.log('Platform:', process.platform);
console.log('Run from folder:', process.cwd());
console.log('This file is in:', __dirname);

// 4. The path module
const file = path.join(__dirname, 'data', 'menu.json');
console.log('join:', file);
console.log('basename:', path.basename(file));   // menu.json
console.log('dirname:', path.dirname(file));     // .../data
console.log('extname:', path.extname(file));     // .json
console.log('parse:', path.parse(file));
console.log('resolve:', path.resolve('menu.json'));
process memberGives you
process.argvArray of command-line arguments
process.envEnvironment variables (strings)
process.cwd()Folder the command was run from
process.pid / process.platform / process.versionProcess ID / OS / Node version
process.exit(code)Stop the program (0 = success, 1 = failure)

Must-remember points

  • argv[0] = node, argv[1] = script file, your arguments start at argv[2].
  • process.env values are strings: '3000' + 1 is '30001'. Convert with Number().
  • path.join glues pieces; path.resolve always returns an absolute path.
  • __dirname = folder of the current file; process.cwd() = where you ran node.
  • Node 20.6+ can load a .env file: node --env-file=.env app.js.

Self-check: answer out loud, then reveal

  1. Why do we write process.argv.slice(2)?
    argv[0] is node and argv[1] is the script; user arguments start at index 2.
  2. What type are values in process.env?
    Strings (or undefined if not set).
  3. path.join vs path.resolve.
    join just glues pieces (may be relative); resolve always gives an absolute path.
  4. __dirname vs process.cwd().
    __dirname = folder of the current file; cwd() = folder where the command was run.

HTTP & REST API Fundamentals

Big idea: the client sends a request; the server sends back exactly one response.
Analogy: a restaurant. Your order slip has what you want (method + URL), notes (headers) and details (body). The kitchen sends back a plate with a label saying how it went (status code).
PartRequestResponse
First lineMethod + URL: GET /menuStatus: 200 OK
HeadersContent-Type, AuthorizationContent-Type, Location
BodyData sent (POST/PUT/PATCH)The result (HTML, JSON …)

HTTP fundamentals

  • Stateless: each request is independent; the server does not remember the previous one.
  • Client-server: the client always starts; the server only answers.
  • Port 80 for HTTP, 443 for HTTPS (encrypted).
  • URL parts: http://localhost:3000/api/menu/2?size=large = protocol, host, port, path, query.

REST principles

REST is a style for designing APIs: URLs name resources (nouns), HTTP methods say the action (verbs).

  1. Client-server: frontend and backend are separate.
  2. Stateless: every request carries what it needs (e.g. a token).
  3. Uniform interface: standard URLs, methods and JSON.
  4. Cacheable: responses say if they can be cached.
  5. Layered system: proxies and load balancers can sit in between.
Not RESTful (verb in URL)RESTful (noun + method)
GET /getAllItemsGET /api/menu
POST /addItemPOST /api/menu
GET /deleteItem?id=2DELETE /api/menu/2

Methods and status codes are covered in full in Segment 12.

  1. What does stateless mean?
    Each request is independent; the server keeps no memory of earlier requests.
  2. Name the three parts of an HTTP request.
    Request line (method + URL), headers, body.
  3. List four REST principles.
    Any four: client-server, stateless, uniform interface, cacheable, layered system.
  4. Rewrite GET /removeUser?id=9 in RESTful form.

HTTP Server with Node.js

Big idea: http.createServer() runs ONE function for every request. You check req.method and req.url (routing) and reply with res.
Analogy: a receptionist. Every visitor comes to the same desk; the receptionist reads the slip and points them to the right room. Unknown room? 404.

Example A: the smallest server (memorise it)

hello.js
// hello.js   ->   run: node hello.js, then open http://localhost:3000
const http = require('http');

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain' });  // status + headers
  res.end('Hello from ChaiCart!');                         // body, then finish
});

server.listen(3000, () => console.log('Server on http://localhost:3000'));

Example B: routing, JSON and reading a request body

server.js
// server.js   ->   run: node server.js
const http = require('http');

const menu = [
  { id: 1, name: 'Masala Chai', price: 20 },
  { id: 2, name: 'Samosa', price: 15 },
];

// helper: send a JSON response
function sendJSON(res, status, data) {
  res.writeHead(status, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify(data));
}

const server = http.createServer((req, res) => {
  const { method, url } = req;

  // GET /
  if (method === 'GET' && url === '/') {
    res.writeHead(200, { 'Content-Type': 'text/plain' });
    return res.end('Welcome to ChaiCart!');
  }

  // GET /menu
  if (method === 'GET' && url === '/menu') {
    return sendJSON(res, 200, menu);
  }

  // GET /menu/2
  if (method === 'GET' && url.startsWith('/menu/')) {
    const id = Number(url.split('/')[2]);
    const item = menu.find(i => i.id === id);
    if (!item) return sendJSON(res, 404, { error: 'Item not found' });
    return sendJSON(res, 200, item);
  }

  // POST /menu   body: {"name":"Bun","price":10}
  if (method === 'POST' && url === '/menu') {
    let body = '';
    req.on('data', chunk => { body += chunk; });   // body arrives in pieces
    req.on('end', () => {
      try {
        const { name, price } = JSON.parse(body);
        const newItem = { id: menu.length + 1, name, price };
        menu.push(newItem);
        sendJSON(res, 201, newItem);
      } catch {
        sendJSON(res, 400, { error: 'Invalid JSON' });
      }
    });
    return;
  }

  // anything else
  sendJSON(res, 404, { error: 'Route not found' });
});

server.listen(3000, () => console.log('Server on http://localhost:3000'));
req / resUse
req.method, req.url, req.headersWhat the client asked for
req.on('data') / req.on('end')Read the request body in chunks
res.writeHead(status, headers)Set status code and headers
res.end(body)Send the body and finish. Always required
Notice: routing, reading the body and setting headers is a lot of manual work. That is exactly the problem Express solves in Part 2.

Self-check: answer out loud, then reveal

  1. Write a server that replies "OK" on port 5000.
    require('http').createServer((req, res) => res.end('OK')).listen(5000);
  2. Why must every request end with res.end()?
    It finishes the response; without it the client keeps waiting.
  3. How do you read a POST body in plain Node?
    Collect chunks in req.on('data'), then JSON.parse in req.on('end').
  4. How do you route GET /menu vs POST /menu?
    Check both: if (method === 'GET' && url === '/menu') and if (method === 'POST' && url === '/menu').

Express.js Basics

Big idea: Express is a small framework on top of Node's http module. It gives you easy routing and handy req/res helpers.
Analogy: the http module is cooking on a stove from scratch; Express is a ready kitchen with labelled shelves. Same food, much less effort.

Setup

npm init -y
npm install express

Example: your first Express app

app.js
// app.js   ->   run: node app.js
const express = require('express');
const app = express();              // the application object
const PORT = 3000;

const menu = [
  { id: 1, name: 'Masala Chai', price: 20 },
  { id: 2, name: 'Samosa', price: 15 },
];

// GET /  -> send text
app.get('/', (req, res) => {
  res.send('Welcome to ChaiCart!');
});

// GET /menu  -> send JSON (sets Content-Type for you)
app.get('/menu', (req, res) => {
  res.json(menu);
});

// GET /menu/2  -> route parameter
app.get('/menu/:id', (req, res) => {
  const item = menu.find(i => i.id === Number(req.params.id));
  if (!item) {
    return res.status(404).json({ error: 'Item not found' });
  }
  res.json(item);
});

// GET /hello?name=Aman  -> query parameter
app.get('/hello', (req, res) => {
  const name = req.query.name || 'Guest';
  res.send(`Hello, ${name}!`);
});

app.listen(PORT, () => {
  console.log(`Express server on http://localhost:${PORT}`);
});

Segment 8 of 12

Express Middleware

Big idea: middleware is a function (req, res, next) that runs between the request arriving and the route sending a response.
Analogy: airport security checkpoints. Each checkpoint either lets you go on (next()) or stops you (sends a response).
TypeWhere it runsHow to addExample
Application-levelEvery requestapp.use(fn)Logger
Route-levelOnly one routeapp.get('/x', fn, handler)Admin check
Built-inComes with Expressapp.use(express.json())express.json(), express.static(), express.urlencoded()
CustomAnything you writefunction (req, res, next)Logger, auth, timer
Error-handlingWhen an error happens4 params: (err, req, res, next)Send 500

Example: all types in one file

middleware.js
// middleware.js   ->   run: node middleware.js
const express = require('express');
const app = express();

// 1. Built-in middleware
app.use(express.json());              // turns JSON body into req.body
app.use(express.static('public'));    // serves files from the public/ folder

// 2. Custom application-level middleware: runs for EVERY request
function logger(req, res, next) {
  console.log(`${req.method} ${req.url}`);
  next();                             // go to the next function
}
app.use(logger);

// 3. Custom route-level middleware: used only where we attach it
function checkAdmin(req, res, next) {
  if (req.query.key === 'chai123') {
    next();                           // allowed: continue
  } else {
    res.status(403).json({ error: 'Admins only' });  // stop here
  }
}

// Routes
app.get('/menu', (req, res) => {
  res.json([{ id: 1, name: 'Masala Chai', price: 20 }]);
});

app.post('/menu', (req, res) => {
  res.status(201).json({ received: req.body });   // works thanks to express.json()
});

app.delete('/menu/:id', checkAdmin, (req, res) => {
  res.json({ message: `Item ${req.params.id} deleted` });
});

app.get('/crash', (req, res) => {
  throw new Error('Oops!');           // goes to the error handler below
});

// 4. 404 handler: AFTER all routes
app.use((req, res) => {
  res.status(404).json({ error: 'Route not found' });
});

// 5. Error-handling middleware: 4 parameters, always last
app.use((err, req, res, next) => {
  console.log('Error:', err.message);
  res.status(500).json({ error: 'Something went wrong' });
});

app.listen(3000, () => console.log('Running on http://localhost:3000'));

Try it: DELETE /menu/1 gives 403, DELETE /menu/1?key=chai123 succeeds, /crash gives 500, /xyz gives 404. Watch the logger print every request.

Must-remember points

  • Signature: (req, res, next). Error middleware has four: (err, req, res, next).
  • Order matters: middleware runs top to bottom. Put express.json() before routes; the 404 and error handlers last.
  • Every middleware must either call next() or send a response, otherwise the request hangs.

Self-check: answer out loud, then reveal

  1. What is middleware? Write its signature.
    A function between request and response: (req, res, next).
  2. Application-level vs route-level middleware, with an example.
    App-level runs for every request (app.use(logger)); route-level only for one route (app.delete('/x', checkAdmin, handler)).
  3. Name three built-in middleware functions.
    express.json(), express.urlencoded(), express.static().
  4. Why must the error handler have four parameters?
    Express recognises error handlers by their four parameters.
  5. What happens if middleware never calls next() and sends nothing?
    The request hangs and the client eventually times out.

Express Router

Big idea: express.Router() is a mini-app that holds a group of related routes in its own file. You plug it into the main app with app.use().
Analogy: a mall directory. The main gate (app.js) sends you to the right floor (/api/menu, /api/orders); each floor manages its own shops.

Example: modular routing

routes/menuRoutes.js
// routes/menuRoutes.js
const express = require('express');
const router = express.Router();

const menu = [
  { id: 1, name: 'Masala Chai', price: 20, type: 'drink' },
  { id: 2, name: 'Samosa', price: 15, type: 'snack' },
  { id: 3, name: 'Cold Coffee', price: 40, type: 'drink' },
];

// GET /api/menu        and   GET /api/menu?type=drink
router.get('/', (req, res) => {

MVC Architecture

Big idea: split the app into Model (data), View (what the user sees) and Controller (logic that connects them). This is called separation of concerns.
Analogy: a restaurant. The Model is the store room (ingredients/data). The Controller is the chef (takes the order, gets ingredients, prepares). The View is the plated dish the customer sees. The Route is the waiter who takes the order to the right chef.
PartJobShould NOT
ModelStore and manage data (array, file, database)Know about req/res
ViewShow data (HTML template or JSON)Contain business logic
ControllerRead request, call model, send responseStore data directly
RouteMap URL + method to a controller functionContain logic

Folder structure

chaicart-mvc/
├── app.js                     entry point: setup + mount routes
├── package.json
├── models/
│   └── menuModel.js           M: data and data functions
├── controllers/

├── routes/

└── views/

Benefits: each file is small and has one job, teams can work in parallel, you can switch the data store (array to MongoDB) by changing only the model, and testing is easier.

Model

models/menuModel.js
// models/menuModel.js  (data lives in an array; later this could be a database)
let menu = [
  { id: 1, name: 'Masala Chai', price: 20 },
  { id: 2, name: 'Samosa', price: 15 },
];
let nextId = 3;

function getAll() {
  return menu;
}

function getById(id) {
  return menu.find(item => item.id === id);
}

function create(name, price) {
  const item = { id: nextId++, name, price };
  menu.push(item);
  return item;
}

function update(id, changes) {
  const item = getById(id);
  if (!item) return null;
  Object.assign(item, changes);       // copy new values onto the item
  return item;
}

function remove(id) {
  const before = menu.length;
  menu = menu.filter(item => item.id !== id);
  return menu.length < before;        // true if something was deleted
}

module.exports = { getAll, getById, create, update, remove };

Controller

controllers/menuController.js
// controllers/menuController.js
const Menu = require('../models/menuModel');

// GET /api/menu
function getAllItems(req, res) {
  res.json(Menu.getAll());
}

// GET /api/menu/:id
function getItem(req, res) {
  const item = Menu.getById(Number(req.params.id));
  if (!item) return res.status(404).json({ error: 'Item not found' });
  res.json(item);
}

// POST /api/menu
function createItem(req, res) {
  const { name, price } = req.body || {};   // {} if no JSON body was sent
  if (!name || typeof price !== 'number') {
    return res.status(400).json({ error: 'name and price (number) are required' });
  }
  const item = Menu.create(name, price);
  res.status(201).json(item);
}

// PUT /api/menu/:id  (replace: both fields required)
function replaceItem(req, res) {
  const { name, price } = req.body || {};
  if (!name || typeof price !== 'number') {
    return res.status(400).json({ error: 'PUT needs name and price' });
  }
  const item = Menu.update(Number(req.params.id), { name, price });
  if (!item) return res.status(404).json({ error: 'Item not found' });
  res.json(item);
}

// PATCH /api/menu/:id  (update only the fields sent)
function updateItem(req, res) {
  const body = req.body || {};
  const changes = {};
  if (body.name !== undefined) changes.name = body.name;
  if (body.price !== undefined) changes.price = body.price;

  const item = Menu.update(Number(req.params.id), changes);
  if (!item) return res.status(404).json({ error: 'Item not found' });
  res.json(item);
}

// DELETE /api/menu/:id
function deleteItem(req, res) {
  const deleted = Menu.remove(Number(req.params.id));
  if (!deleted) return res.status(404).json({ error: 'Item not found' });
  res.sendStatus(204);
}

// GET /menu-page  (HTML view)
function showMenuPage(req, res) {
  res.render('menu', { items: Menu.getAll() });
}

module.exports = {
  getAllItems, getItem, createItem, replaceItem, updateItem, deleteItem, showMenuPage,
};

Why req.body || {}? in Express 5 (the current version), req.body is undefined when the client sends no JSON body or forgets the Content-Type: application/json header. Destructuring undefined would crash with a 500, so we fall back to an empty object and return a clean 400 instead.

HTTP Codes & Methods: Quick Reference

Big idea: the method says what the client wants to do; the status code says how it went.

HTTP methods

MethodMeaningHas body?Safe?Idempotent?Express example
GETRead dataNoYesYesapp.get('/menu', ...)
POSTCreate newYesNoNoapp.post('/menu', ...)
PUTReplace whole itemYesNoYesapp.put('/menu/:id', ...)
PATCHUpdate some fieldsYesNoNo*app.patch('/menu/:id', ...)
DELETERemoveUsually noNoYesapp.delete('/menu/:id', ...)

Safe = does not change data. Idempotent = sending it once or ten times gives the same final result (ten DELETEs of item 2 still leave it deleted; ten POSTs create ten items). *PATCH can be idempotent depending on how it is written.

PUT vs PATCH

// Item before:      { id: 2, name: 'Samosa', price: 15 }

// PUT /menu/2       body: { name: 'Samosa', price: 18 }   -> send EVERYTHING
// Item after:       { id: 2, name: 'Samosa', price: 18 }

// PATCH /menu/2     body: { price: 18 }                    -> send only the change
// Item after:       { id: 2, name: 'Samosa', price: 18 }

Example: every common status code in one Express file

status-demo.js
// status-demo.js   ->   run: node status-demo.js
const express = require('express');
const app = express();
app.use(express.json());

const users = ['aman'];

app.get('/ok', (req, res) => res.status(200).json({ message: 'All good' }));          // 200

app.post('/users', (req, res) => {
  const { username } = req.body || {};
  if (!username) return res.status(400).json({ error: 'username required' });       // 400
  if (users.includes(username)) return res.status(409).json({ error: 'already exists' }); // 409
  users.push(username);
  res.status(201).json({ username });                                                // 201
});

app.delete('/users/:name', (req, res) => {
  if (!users.includes(req.params.name)) {
    return res.status(404).json({ error: 'not found' });                           // 404
  }
  users.splice(users.indexOf(req.params.name), 1);
  res.sendStatus(204);                                                               // 204
});

app.get('/old-menu', (req, res) => res.redirect(301, '/ok'));                        // 301

app.get('/dashboard', (req, res) => {
  const token = req.headers.authorization;
  if (!token) return res.status(401).json({ error: 'Please log in' });              // 401
  if (token !== 'admin') return res.status(403).json({ error: 'Admins only' });     // 403
  res.json({ message: 'Welcome, admin' });
});

app.get('/broken', (req, res) => {
  throw new Error('Database exploded');                                             // 500
});

app.use((err, req, res, next) => {
  res.status(500).json({ error: err.message });
});

app.listen(3000, () => console.log('Try the routes on http://localhost:3000'));
Asked every year: 401 = "who are you?" (not logged in). 403 = "I know who you are, and the answer is no."

8Middleware = (req, res, next); order matters; error handler has 4 params.

Top mistakes that cost marks

  1. exports = {...} instead of module.exports = {...}.
  2. No 'error' listener on an EventEmitter.
  3. Expecting async readFile results on the next line.
  4. Comparing req.params.id (a string) with a number without Number().

  7. Putting the 404 handler before your routes.
